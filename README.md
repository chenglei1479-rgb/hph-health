# Deep Research Agent

一个独立桌面版医学科研智能体，面向医学文献综述、研究方案设计、统计分析和论文写作。首版复用 Electron、React、TypeScript 科研运行时，并为医学科研任务增加专属工作台、任务模板和研究安全约束。

## 首版流程

- **研究新颖性评估**：先让研究者确认日英检索概念，再检索当前可用的 PubMed、Crossref、OpenAlex 和 ClinicalTrials.gov 来源，整理既有研究、证据冲突、研究空白和相关进行中试验，生成带来源与检索范围说明的 Research Gap Map。jRCT 提供官方人工核验入口；不会对其页面进行自动抓取，也不会把未查询的来源说成已检索。
- **证据综述**：先确认 PICO、数据库、时间范围和纳入标准，再整理可追溯的 PMID/DOI 证据表。
- **研究方案**：根据研究问题形成可编辑草稿，将缺失的研究设计、结局、伦理和注册信息列出来供研究者确认。
- **数据分析**：在对话中附加匿名化 CSV 后，先检查变量、单位、编码、重复记录、范围、缺失情况和描述统计；说明数据质量问题并推荐统计方法。研究者确认研究设计、统计计划以及 Table 1/图表方案后，才运行可用的 Python/R 环境，生成表格、图形、Methods/Results 草稿和可复现代码。保留原始文件，并记录代码与软件版本、输入校验和、分析参数及实际输出；无法实际执行时明确说明，不把代码草稿说成已完成分析。
- **论文写作**：只依据已核实来源、用户提供的方案和真实研究结果起草，并将缺失信息标为待补充。
- **英文学术写作**：把日文研究笔记转化为符合 Methods、Results 或 Discussion 语境的医学英语。需要根据上下文判断章节；上下文不足时先询问。按目标期刊风格润色前核对其最新投稿要求，不补造研究信息。

选择流程后，应用会创建相应的研究项目，并把任务草稿放入新的对话输入框。草稿不会自动发送，研究者可以先检查、修改再启动 Agent。
桌面配置、项目库、运行环境和远程任务目录沿用现有本机路径；原版 Open-Science 的数据与任务不会被自动导入或接管。

## 可追溯与研究者确认

工作流按 **Research Question → PICO → PubMed Search → Evidence Table → Hypothesis → Study Design → Statistical Plan → Results → Manuscript** 推进，每次只展示当前阶段的草稿和需要研究者作出的决定。PICO、检索策略、拟纳入文献、研究设计与统计计划都需要研究者明确确认；论文草稿也需要最终审核。未获确认不会被视为批准。

重要科研结论应就近列出已核实的 PMID、可用时的 DOI、期刊、年份、支持性证据和可点击来源，并区分来源原文与 Agent 的解释。研究数据任务应尽量保持 **Answer → Evidence → Data → Code → Result** 可追溯，包括匿名化输入、变量与队列筛选、排除规则、分析代码与版本、方法、参数和实际计算输出。文献检索、Python/R 执行和文件导出能力取决于当前可用的来源、模型、工具及运行环境，界面中的任务草稿本身不会自动完成这些操作。

## Research Memory

每个项目都有独立的项目记忆。开启 **Settings > Memory** 后，Agent 可在同一项目的新会话中回想研究问题与假设、PICO/主要终点、纳入排除标准、队列定义、分析决策及修改原因、论文或审稿意见修订记录，以及待解决问题。医疗科研工作流要求先向研究者展示回想内容并核对，再把研究者明确确认的事实保存为带日期的项目记录；关键决策变化会追加新记录并保留先前记录。研究者可以在 **Settings > Memory** 按项目查看、编辑和删除记忆。

Research Memory 只用于跨会话衔接，不是审计日志，也不能替代 protocol、原始来源、分析代码、数据或论文文件。仅保存研究者确认的非识别性研究事实，不保存患者身份信息或原始数据。若 Memory 关闭或工具不可用，Agent 应说明无法跨会话回想，并提供可供研究者自行保存的状态摘要。

新颖性评估只代表在明确检索范围和日期下的初步判断，不能证明“此前从未有人研究”。jRCT 页面提示避免超出个人使用范围的自动化大规模数据收集，因此应用只链接官方页面供研究者手动核验。

## 本地启动

在安装 Node.js 版本与 `.nvmrc` 匹配的开发环境后，运行：

```bash
npm ci
npm run dev
```

首次启动时，在引导页面配置模型提供方和 Agent 运行时。可检索的医学文献、连接器和分析工具取决于当前配置及授权；若某项来源不可用，Agent 应说明限制，不得声称已完成检索。

## 手机浏览器版

DRA 可由运行中的桌面端提供浏览器界面。先在桌面端启用远程访问并完成浏览器配对，再用手机打开配对后的 HTTPS 链接。iPhone/iPad 可从 Safari 分享菜单添加到主屏幕，Android 可从 Chrome 菜单安装或添加到主屏幕。手机端是桌面端的浏览器入口；桌面主机需要保持运行和联网，手机离线时不能执行研究任务。网页不使用离线 Service Worker 缓存。上传到网页的文件会传到运行 DRA 的主机；临床数据应先去标识化，并确认模型与连接器的数据传输设置。

## 医学研究边界

本应用用于学术研究工作，不提供患者诊断、分诊或治疗建议，也不替代临床专业判断。不要上传姓名、病历号等可识别患者身份的信息。方案、分析和论文均是需要研究者核对的草稿；研究者应核实引用、方法、结果、伦理要求与注册信息。涉及日本的研究时，应用只提示需要向机构及官方来源核实的事项，不代替合规审查。
